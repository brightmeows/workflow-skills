# AI 味审计（ai-taste）

审计中文文本的表达与句式：找出“读起来像 AI 写的”具体病征，逐条给出证据和判定，按需改掉。服务两类文本：写给代理的提示词文档（AGENTS.md、SKILL.md），以及散文、评论、公告一类通用文本。

## 边界

- 本技能管**表达与句式**：空话、堆砌、模板化节奏、翻译腔、伪精确。结构与信息设计（内容放哪、怎么剪除、完成判据是否清晰）归 `writing-for-agents`；逐行猎取无效指令（no-op）也归它，本技能的模式表不重复覆盖。
- 审计的是**文本质量信号**，不判作者身份。病征在人类写手（赶稿、二语写作、文体压缩）笔下同样出现。命中模式等于“值得检查”，不等于“AI 写的”。
- 输出**命名病征**与自检结果，不给“AI 概率百分比”——那种数字没有可核查的依据，给了就是编的。

## 先划边界：这些不算病

这一节放在所有模式之前，因为误伤比漏检的代价高：把正常风格当病改掉，产出比原文更糟。

| 特征 | 为什么单独出现不算病 |
|---|---|
| 列表、编号步骤、加粗术语 | 提示词文档的正常骨架 |
| 对称小标题、工整结构 | 结构本身不是病，空才是 |
| 破折号多、排比多 | 中文本有的用法，鲁迅用得比谁都凶 |
| 三段式、“不是……而是……” | 常规修辞，人类用了两千年 |
| 成语、比喻、四字词 | 修辞本身无罪 |
| 文风华丽或简练 | 个人风格差异，不是病 |

正确用法：这些特征只有在**高密度扎堆、同时命中多条模式**时才作为旁证，单独命中一律放过。改写时降密度，不搞零容忍。

## 双轨路由

先判文本类型，再加载对应模式表。审计前必读对应文件全文，靠记忆套规则不算审计：

- **提示词文档**：AGENTS.md、CLAUDE.md、SKILL.md、系统提示词、写给代理的指令与规则。读 [references/prompt-patterns.md](references/prompt-patterns.md)。这类文档的病是“看着像规则，代理执行不动”：空原则、黑话、模板化小标题撑空章节。
- **散文与通用文本**：评论、博客、公告、总结、文案。读 [references/prose-patterns.md](references/prose-patterns.md)。这类文本的病是模板化节奏与伪个人视角。

混合文档（比如带大量说明文字的技能）：两个表都过，prompt 模式查指令句，散文模式查叙述段。

## 审计工作流

1. 通读全文，记下朗读时卡壳的位置和第一印象的病征方向。
2. 对照模式表逐条过。每条命中都要：引用原句、执行该条的自检动作、给出判定（成立或豁免）。自检动作不通过的命中不成立，记入保留意见。
3. 输出报告，格式见下。命中超过 8 条时按严重程度取前 8，其余归入“其他小问题”一行带过。
4. 审计到此为止；用户要求改写才进改写流程。

### 报告格式

```markdown
## 体检结论
（2–3 句：主要病征类型、严重程度、整体判断。不给 AI 概率。）

## 逐条病征

### 1. [病征名] · 严重程度
> 原句原文照抄

**自检**：[该条自检动作的执行结果]
**建议**：改成什么样

（每条一节，按严重程度排序，最多 8 条）

## 保留意见
（看着像但其实没问题的地方，说明豁免理由——防止用户过度纠正。）
```

## 改写流程

用户要求改写时：

1. 先在心里完成审计，确认全文目的一句话；不清楚就问用户。
2. 按顺序动刀，先砍后补：第一遍删（无目的细节、空话、答不上自检的修辞）；第二遍修逻辑硬伤；第三遍调节奏；第四遍补具体。
3. 输出改写稿、关键改动表（5–8 条，附理由）、需要用户补充素材的清单。

### 改写红线

1. 不改事实：人名、地名、数据、时间、引语一个字不动。
2. 不改作者观点：哪怕站不住，那也是他的稿子。
3. 不编素材：缺细节就问用户，编一个具体往事是在制造新的 AI 味。
4. 不把文章改寡淡：目标是提高信息密度和真实感，铲平修辞得到的是说明书。
5. 好句子原样留着，并在报告里说明“这段没动”。
6. 交付前核对：新增的每个具体信息能否在原文找到；独立信息、限定、归因是否完整。

## 预防模式

[references/prevention-block.md](references/prevention-block.md) 是同一套病征的正面指令形态，一个可直接嵌入系统提示词或 AGENTS.md 的规则块。两种用法：写文本前贴进上下文当写作约束；写完后对照它自检。规则块的每一条都对应模式表里的病征，两边不要各改各的。
