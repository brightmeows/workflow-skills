# 预防规则块

同一套病征的正面指令形态。两种用法：写文本前整块贴进上下文（系统提示词、AGENTS.md、任务提示）当写作约束；写完后对照自检。每一条都对应 SKILL.md 模式表里的病征，改任何一边要同步另一边。

## 通用写作约束（散文、文档通用）

```markdown
## 写作约束

- 一个名词最多挂一个定语；定语超一个就拆成短句，按条件顺序排开。
- 写完一句，删掉限定词（其实、往往、某种程度上、至关重要、必要的话）重读；意思不变就不留。
- 连续同构分句不超过 2 个；第三句换句式，或展开成比前两句长一倍的具体场景。
- 每段回答得出“推进了什么”（信息、情节、论点、情绪四选一）；答不上就删。
- 比喻先答三问：本体喻体共享什么属性？这是本体最需要说明的吗？喻体比本体好懂吗？答不出就直说。
- 例子和细节过替换测试：换成另一对人、另一个系统还成立，就是套路；换成只属于此处的具体细节。
- 结尾停在具体的判断或事实上，用成语和排比收束前先问：展开说是什么？
```

## 提示词文档追加约束（AGENTS.md、SKILL.md、系统提示词）

```markdown
## 指令写作约束

- 每条指令过“完成与未完成可分辨”检查：代理读完知道何时算做到、何时不算。给不出判据的原则删掉或补上判据。
- 章节标题写“这节处理什么处境”，不把结论写进标题。
- 商业黑话（赋能、抓手、闭环、颗粒度、心智、底层逻辑）一律换成说清具体做什么；技术语境的本义用法保留。
- 数字承诺必须带基线或度量方式（“构建时间从 9 分钟到 40 秒”），没有基线就改定性描述加验收方式。
- “我们”不预设读者感受；“我”在一个段落只做一次锚点，后面让事实推进。
```
