# 取数纪律

信息最好一次拿完整。截断式抽样看着省事，实际要重试，而重试比多读一轮贵。

## 一次拿全

- 不用 `head`、`tail`、`grep` 做抽样替代读取
- 读文件就读完整的相关范围，大文件分块读到底
- 错误与警告完整拿，不只看最后一行
- 搜索与技能正文完整看，不靠片段拼全貌

## 先定位再回读

`grep` 只用来精确定位，带 `-C` 取上下文；定位到之后，完整读目标所在的章节或函数。

判断标准：结论依赖的每一段原文，都读过它的完整边界。拿片段推全貌，是取数环节最常见的错误来源。

## 让工具自己精简

- 优先用工具自带的精简开关：`--quiet`、`--message-format=short`、`--json`、`--no-headers`
- 取字段用 `jq` 精确提取，别跑完整输出再叠 `head` / `tail` / `grep`
- 结构化输出优先于文本输出：能拿 JSON 就不解析表格

## 并行与串行

- 互不依赖的操作一轮做完，不发一个等一个
- 有依赖、或写同一份状态的操作串行执行，免得互相覆盖
- 合并独立调用时，先把失败隔离住：一个失败不该带走同批其他结果

## 大输出落盘

输出很长、或重跑很贵时，先写进缓存目录再从文件读：

```bash
mkdir -p /tmp/agent-cache
<command> > /tmp/agent-cache/out.txt
```

实时数据和状态查询每次现查，不缓存。

## 上下文兜底

拿全信息是本分，不是奢侈：上下文管理由运行时兜底（压缩、摘要、会话持久化）。

只有收到明确的上下文受限提示时才需要精简，而且精简的是**获取范围**，不是改动范围。

## 完成判据

- 结论所依赖的原文，都读过完整范围
- 没有为了少读几行而漏掉错误、警告或后续章节
- 长输出落在磁盘，可复查、可复用，不用重跑

维护理由、证据与粒度裁决见仓库 `docs/retrieval-discipline-rationale.md`（不随技能分发）。
