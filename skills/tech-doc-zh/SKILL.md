# 中文技术文档清晰度（tech-doc-zh）

目标是读者读一遍就照着做、不会做错。AI 味问题（结构可预测、金句铸句、缓冲词）归 ai-taste；中文标点与弯引号归主指令文件的表达规范。

## 用法

先判文档类型，定适用强度。写作时按篇法、句法、字法三层起草，预防块可整段嵌入写作提示词；审计时逐层对照，命中就引原句、走判定动作，记入保留意见。审计即止，用户要求改写才动笔；改写按替换对与句法动作执行。可与 ai-taste 同跑一份文档：它查 AI 味，本技能查清晰度，两条轴互不替代。

## 适用强度

- **完整应用**：操作手册、安装与部署步骤、故障排查、运维 runbook、安全警告、多步骤 API 调用流程。
- **选择性应用**：API 概念说明、常见问题、更新日志、产品能力说明——只执法术语一致、指代明确与事实保真，不把所有句子改成操作步骤。
- **不应用**：品牌与落地页文案、叙事性文章、法律原文与正式引用、需保留作者风格的内容、极短的按钮与导航标签。

## 豁免线

- **技术名词与项目术语不进替换对**：项目专属名词、API 名、产品动词按项目术语表原样使用（STE 的技术名词豁免机制）。
- **叙事与风格文本不归本技能**：散文的语域、修辞与节奏归 ai-taste 散文轨。
- **引用原文不改写**：法条、合同、第三方文档引用保持原样。
- **短标签不受句法约束**：按钮、导航、字段名按 UI 惯例。
- **代码块与图表内文字不审**。

## 篇法：确定性

1. **结论前置**：操作类文档先说做什么、成功状态是什么，再讲条件与例外；汇报类文档首句给结论，不铺垫。
2. **一句一义**：一个句子只承载一个主要断言或一条指令；两个动作同时发生或构成一个不可分操作，才可合写。
3. **条件前置**：必要条件写在动作之前，逗号隔开——“如果测试失败，停止部署”；读者必须先知道条件才能执行时，条件不许后置。
4. **禁免责叠甲**：不写“可能不完全准确”“仅供参考”式生成时刻免责；真实限制写成例外条款，一条一处，写在对应动作旁边。
5. **事实保真**：不新增来源没有的数字、日期、时限、能力或结论；不删警告、限制、例外、单位、默认值与失败处理；不改变“可能、建议、通常”表达的确定程度。

## 句法：句子与段落

1. **句长分级**：单句尽量 20 字以内；20–29 字可接受；30–39 字语义必须明确才可接受；超过 40 字不可接受——拆句或改编号列表。
2. **指代消歧**：代词（其、该、此、这）的指代必须唯一；读出发歧义就还原成名词。
3. **主动语态**：施事已知时用主动句；指令用祈使——“重启服务”，不是“服务应当被重启”或“需要重启服务”。
4. **竹节句**：连续“的”字定语不超过 3 个；修饰语过长就拆短句，按条件顺序排开，别让读者读了几十个字还没见到核心动词。
5. **段落纪律**：一段只说一事，不超过 6 句；并列步骤用编号列表，不用长句串联。

## 字法：术语与选词

1. **术语一致**：一个概念一个首选术语，不为避免重复轮换同义词；缩写首次出现给全称，后文保持同一写法。
2. **一词一义**：同一个词在文档内不换含义；存在多义时换更具体的词消除歧义，不做机械替换。
3. **替换对**（起步清单，按实战增长，三次才抽象）：

   | 避免 | 改为 |
   |---|---|
   | 进行部署 / 进行配置 / 进行更新 | 部署 / 配置 / 更新 |
   | 对 X 进行 Y | 直接写 Y |
   | 做了一个 XX 操作 | 配置了 XX |
   | 相关情况 / 相关内容 | 删，或写明具体对象 |
   | 如果需要的话 | 如需 |
   | 大概 / 基本上 / 左右 | 删，或给出真实区间 |
   | 需要注意的是 | 注意：（或删） |

4. **黑话不重复设格**：赋能、抓手、闭环等归 ai-taste 黑话格；本技能只管技术语境的选词精度。

## 改写红线

- **事实保真优先于句法整洁**：改写不新增、不丢失、不弱化事实；改完逐条核对篇法第 5 条。
- **不为句长指标牺牲内容**：该长的句子拆开写，不删条件与例外凑数。
- **项目专名不改**：术语表内名词与动词原样保留。
- **审计即止**：用户要求改写才动笔。

## 预防块

技术文档写作的正面约束，比审计判据更严；可整段嵌入写作提示词或 AGENTS.md，也可写完后对照自检。预防块是判据的正面重述，改判据时同步改这里。

```markdown
## 技术文档写作约束

- 一句一义：每句一个断言或一条指令；两个动作同时发生才可合并。
- 条件写在动作之前，逗号隔开。
- 代词指代唯一；有歧义就还原成名词。
- 单句尽量 20 字内；超过 40 字必须拆或改列表。
- 一个概念一个术语，不轮换同义词；缩写首次出现给全称。
- 警告与限制写在对应动作旁边，不集中堆在文末。
- 指令以动词开头；不用“应当被”“需要进行”。
- 交付前核对：数字、单位、默认值、失败处理都在，且来源有据。
```
